# AGENTS.md

Operating rules for agents (Claude Code and maestro-directed) working in this
repo.

## What this repo is

A spec-driven legacy-modernization demo lab. **Product intent precedes design
precedes code.** Every unit of work traces to a functional spec
(`docs/product/FS-*.md`) and respects the locked ADRs
(`docs/design/decisions/`).

## Hard rules

1. **Spec-first.** Do not build features that have no FS spec. If scope is
   missing, propose a spec change, don't improvise code.
2. **Scope discipline is the product.** ADR-0002: one domain, one Spring
   service. Resist the urge to add services, Kafka, or extra domains — the
   restraint is part of the portfolio story. (Debezium CDC is the only
   sanctioned stretch, M3, gated.)
3. **Honesty rule (ADR-0004).** Nothing in code, docs, or commit messages may
   imply production hardening, load testing, or operational history that
   doesn't exist. "Demonstration lab, learning depth, AI-assisted build" is the
   claim — keep it true.
4. **The legacy code must stay legacy.** PL/SQL under `legacy/` is written in
   authentic 2000s enterprise style (package-heavy, side-effectful,
   sparsely commented). Do not modernize, lint, or "improve" it — it is the
   specimen. Bug-for-bug behavior is what parity tests protect.
5. **Assessment artifacts keep their receipts.** Everything under
   `assessment/` generated by an agent must commit the prompt/agent definition
   alongside the output. That provenance *is* the differentiator.
6. **Local-first (ADR-0001).** `docker compose up` must always work end-to-end
   on a clean machine. Terraform must `plan` cleanly but is never auto-applied.
7. **PR-only.** Agents raise PRs; the human merges. Conventional commits.

## Layout (target)

```
legacy/        Oracle XE schema, PL/SQL packages, ORDS config, seed data   (FS-0001)
assessment/    AI-generated assessment artifacts + prompts/agents          (FS-0002)
services/      pricing-service (Spring Boot 3, Java 21)                    (FS-0003)
strangler/     routing layer + per-endpoint wave config                    (FS-0004)
parity/        golden-master corpus, dual-run harness, diff reports        (FS-0005)
infra/         Terraform (EKS/RDS) + local kind profile; compose at root   (FS-0006)
docs/          specs, ADRs, roadmap
```

## Verification

- Java: `./mvnw verify` in `services/pricing-service` (unit + slice +
  Testcontainers; Docker required).
- Parity: `make parity` — replays the golden corpus against both stacks and
  fails on diff (see FS-0005 for the tolerance contract).
- Full stack: `make up && make smoke`.
