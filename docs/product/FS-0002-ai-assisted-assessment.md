# FS-0002 — AI-assisted assessment

- **Status:** draft
- **Raised:** 2026-07-22
- **Owner:** @farid (architect)
- **Milestone:** M0

## Why

"AI-assisted software modernization" now appears verbatim in modernization-
architect JDs. Everyone will claim it; nearly nobody can show the artifact
*and* the tooling that produced it. Committing both turns a resume line into
evidence — and demonstrates exactly what the assessment phase of a real
engagement would produce on day one.

## Scope

1. **Artifacts** under `assessment/` (all generated over `legacy/` source):
   - `business-rule-catalog.md` — every business rule extracted from the three
     packages, each with: rule ID, plain-language statement, source anchor
     (package/procedure/line), and migration-relevant notes (side effects,
     quirks — e.g. the TRUNC rounding).
   - `dependency-map.md` — Mermaid diagrams: package↔table CRUD matrix,
     package↔package calls, endpoint↔package routing.
   - `classification.md` — per module: complexity score, coupling notes, and
     an **R-lane verdict** (rehost / replatform / refactor / retire) with
     one-paragraph rationale each.
   - `wave-plan.md` — migration waves with explicit dependencies and per-wave
     exit criteria (parity gates, FS-0005); wave 1 = pricing quote.
   - `effort-estimate.md` — t-shirt estimates per module with stated
     assumptions.
2. **Provenance** under `assessment/agents/`: the prompt / agent definition /
   workflow script that generated each artifact, named to pair 1:1 with its
   output. A `README.md` explains how to re-run.
3. **Human-in-the-loop marker**: each artifact carries a short "architect
   review" footer noting what the human corrected or overruled — the honest
   division of labor (and itself a talking point: agents draft, architect
   decides).

## Out of scope

- A reusable assessment *product* or framework (that ambition belongs to
  maestro, not this lab).
- Assessment of code outside `legacy/`.
- Automated effort-estimation tooling (estimates are architect judgment,
  agent-drafted).

## Acceptance criteria (EARS)

- EACH artifact under `assessment/` SHALL have a paired generator under
  `assessment/agents/` and SHALL be reproducible from it (allowing for
  LLM nondeterminism in wording, not in substance).
- THE business-rule catalog SHALL anchor every rule to package + procedure
  (+ line where stable) in `legacy/`, and SHALL include the TRUNC rounding
  quirk and the PLACE_ORDER side-effect set.
- THE classification SHALL give each module exactly one R-lane verdict with a
  rationale, and the wave plan SHALL be consistent with those verdicts and
  with the dependency map.
- EACH artifact SHALL carry an architect-review footer distinguishing
  agent-drafted from human-decided content.
- THE wave plan SHALL define, for every wave, an exit criterion expressed as a
  parity gate (FS-0005) plus a rollback statement.

## Definition of done

- All five artifacts + paired generators committed; re-run instructions work.
- The wave plan's wave 1 matches what FS-0004 implements (pricing quote
  cutover) — specs and artifacts tell one story.
